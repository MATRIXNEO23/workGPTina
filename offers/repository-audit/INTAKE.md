# Intake minimo cliente

Richiedere soltanto dopo interesse esplicito.

1. URL e branch della repository autorizzata.
2. Problema in una frase e risultato desiderato.
3. Ultimo stato sicuramente funzionante, se noto.
4. Workflow o comando che fallisce e log già condivisibili.
5. Scadenza reale, se esiste.
6. Accesso richiesto: preferire repository pubblica o permesso read-only; scrittura solo con autorizzazione separata.
7. File/aree fuori scope e dati sensibili presenti.
8. Deliverable scelto: solo audit oppure audit più una correzione circoscritta.

Non chiedere password, token, chiavi API o segreti in chat. Se un segreto appare nei log, interrompere la copia, chiedere rotazione/rimozione e usare una versione redatta.
